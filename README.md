# 宿舍账本 —— 宿舍公共开销分摊器

一个**零依赖、单文件、打开即用**的宿舍公共开销分摊工具。把「谁垫了钱、谁该分摊多少、最后谁转给谁多少」一次性算清楚。宿舍人数由用户自己设置（2~12 人，默认 4），四人寝、六人寝、合租房都能用。

- 技术栈：HTML + CSS + 原生 JavaScript（无框架、无库、无后端、无构建）
- 交付形态：单个 `index.html`，双击即可运行
- 数据存储：浏览器 localStorage，刷新/关闭不丢

---

## 一、痛点

大学宿舍里（四人寝最常见，也有五人寝、六人寝、两人间和合租房），公共开销几乎每天都会发生：水电费、聚餐、日用品、打印费……
但现实中算账的过程是这样的：

| 现状 | 带来的问题 |
| --- | --- |
| 每次都是同一个人先垫付 | 垫付的人长期「被欠钱」，心理不平衡 |
| 月底靠微信聊天记录手动加减 | 记录分散、容易漏项，算错还没人发现 |
| 金额是小数，笔算容易出错 | 0.1 + 0.2 这类误差在人多时越滚越大 |
| 通用记账 App 面向个人 | 没有「多人分摊」概念，还要注册登录、上传隐私数据 |
| 算清了「谁欠多少」，却算不出「谁转给谁」 | 4 个人可能产生 6 条欠款关系，逐条转账又麻烦又容易乱 |

所以这个项目要解决的核心问题是：
**把「一堆零散支出」直接变成「一份最少笔数的转账清单」。**

## 二、功能介绍

### 1. 成员管理
- **先用「宿舍人数」的加减步进器设置人数**（2~12，默认 4），再逐个添加姓名。人数没设置时，姓名输入框和「添加」按钮保持禁用，避免"先加人、再回头改人数"的来回折腾。
- 设置后按「已添加 x / 人数」显示进度：未加满时提示「还差 n 人未添加」，加满后提示「成员已满」并自动禁用输入框与按钮。
- 人数是**上限**，不要求必须填满——允许先给 4 个室友记账、第 5 个室友之后再补，硬性凑满反而会挡住正常使用。
- **人数不能改到小于已有成员数**（已有 4 人时不能改成 3），否则等同于凭空删人、会让历史账目失去支撑；非法值（如 20、abc）会被拦截并把输入框回退为原值。步进器的「−」在人数已等于成员数、或已到 2 人下限时会自动置灰，「+」到 12 人上限时同样置灰，从交互上先一步挡住非法操作。
- 重名、空名会被拦截。
- 范围由常量 `MIN_MEMBER_LIMIT = 2`、`MAX_MEMBER_LIMIT = 12`、`DEFAULT_MEMBER_LIMIT = 4` 控制——业务规则没有写死在界面里，要调整范围只需改这几个常量。
- 删除成员时，如果该成员**已有支出记录**（作为付款人或分摊人），拒绝删除并提示原因，避免历史账目被破坏。

### 2. 添加公共支出
- 字段：事项、金额（元，支持两位小数）、付款人、参与分摊的人（多选，默认全选）、日期、分类（水电 / 聚餐 / 日用品 / 打印 / 其他）。
- 付款人、参与分摊的人都是**标签式选择**：点一下标签即可切换，比下拉框少一次展开、比原生复选框更好点按；参与分摊支持「全选 / 全不选」，默认全部成员参与。
- 金额、事项、付款人、参与人全部做了校验，非法输入不会写入数据。

### 3. 自动计算
对每位成员计算三项数据：

| 指标 | 含义 |
| --- | --- |
| 垫付总额 | 该成员作为付款人累计垫付的金额 |
| 应分摊 | 该成员在所有支出中应承担的份额之和 |
| 净余额 | `垫付总额 - 应分摊`；**正数 = 应收**，**负数 = 应付**，0 = 已结清 |

统计表底部给出合计数，所有净余额之和恒为 0（可用于自检数据是否自洽）。

### 4. 最优结算方案
- 根据净余额，用**贪心算法**（每次取最大债权人 + 最大债务人，转账两者中的较小金额）生成转账列表。
- 每一轮必然有一方清零，因此转账笔数不超过 `n - 1` 笔：4 人最多 3 笔，6 人最多 5 笔。
- 支持一键「复制方案」，直接粘贴到宿舍群即可。

### 5. 支出记录
- 列表展示全部支出，按日期倒序排列。
- 每条显示：分类标签、事项、金额、日期、付款人、分摊人（全员参与时显示「全体成员」）。
- 支持逐条删除（二次确认）。

### 6. 数据持久化
- 所有变更实时写入 localStorage（key：`dorm-ledger:v1`），刷新页面数据不丢。
- 隐私模式等存储不可用场景做了异常捕获，不会导致页面白屏。

### 7. 导出：给人看的账单 + 给程序用的备份
这两种需求目的不同，所以刻意拆成两条路径，互不替代：

- **复制账单（给人看）**：一键把整份账单以**纯文本**复制到剪贴板，内容包含总支出、每位成员的垫付/应分摊/应收应付、转账方案、支出明细。可直接粘贴到微信、记事本、备忘录、QQ——**不需要安装任何软件**，也不存在中文乱码问题。
- **导出备份（给程序读）**：生成 `宿舍账本备份-YYYY-MM-DD.json`，包含全部成员与支出，还带有 `id`、分类 key、时间戳等机器信息。它的唯一用途是将来能通过「导入备份」**完整还原数据**。JSON 是结构化数据、天生不适合人阅读，这是格式本身决定的，而不是缺陷——所以它和文字账单是互补关系。
- **导入备份**：读取 JSON 并**经过完整校验**后覆盖当前数据，校验不通过会明确报错，不会把脏数据写进本地。
- 支持「清空数据」（带二次确认）。

### 8. 金额精度
- 内部**全部以「分」为单位的整数**参与运算，显示时才转成元，从根本上避免浮点误差。
- 均摊除不尽时，**余数按参与者顺序每人多分 1 分**，保证拆分结果之和严格等于原金额。

### 9. 安全
- 所有用户输入（成员名、事项名）在渲染前统一经过 `esc()` 做 HTML 转义，防止 XSS。
- Toast 提示使用 `textContent` 赋值，天然不解析 HTML。

## 三、运行方式

### 方式一：直接打开（最简单）
双击 `index.html`，用任意现代浏览器打开即可，无需任何环境。

### 方式二：本地静态服务（推荐，剪贴板 API 等能力更完整）
```bash
# 在 index.html 所在目录执行
python -m http.server 8000
```
然后浏览器访问 <http://localhost:8000>

> 提示：`file://` 协议下 `navigator.clipboard` 可能不可用，代码已做降级处理（`execCommand('copy')`），两种方式都能复制结算方案。

### 使用流程
1. 先在「宿舍人数」里填宿舍有几个人（2~12，默认 4）；
2. 逐个添加宿舍成员（按「已添加 x / 人数」的进度提示，可以只填一部分，之后随时补）；
3. 每发生一笔公共开销就记一笔（选择付款人和参与分摊的人）；
4. 随时查看「账目统计」和「最优结算方案」；
5. 月底按转账列表执行，点击「复制方案」发到宿舍群；
6. 需要把完整账单发给室友看时，点顶部「复制账单」，直接粘贴到微信即可（纯文字，对方无需任何软件）；
7. 定期点「导出备份」保存 JSON（这是给程序用的恢复文件，平时不需要打开它）。

## 四、技术说明

### 4.1 数据结构
```json
{
  "app": "dorm-ledger",
  "version": 2,
  "exportedAt": "2026-10-12T08:00:00.000Z",
  "memberLimit": 4,
  "members": [
    { "id": "x1a2b3c", "name": "张三" }
  ],
  "expenses": [
    {
      "id": "x9z8y7x",
      "title": "9月电费",
      "amountCents": 12850,
      "payerId": "x1a2b3c",
      "participantIds": ["x1a2b3c", "x4d5e6f", "x7g8h9i", "xj0k1l2"],
      "date": "2026-10-08",
      "category": "utility",
      "createdAt": 1760000000000
    }
  ]
}
```
说明：`amountCents` 是**分**；`category` 存英文 key（`utility / meal / daily / print / other`），展示时才映射为中文标签；`memberLimit` 是用户设置的宿舍人数（成员上限），`0` 表示尚未设置。

> 兼容性：`memberLimit` 是 v2 新增字段，**早期导出的 v1 备份仍可正常导入**——`normalizeData()` 检测到没有该字段时，会按「默认 4 人与实际成员数中的较大值」自动补齐，并且始终保证 `memberLimit >= 实际成员数`。数据结构变更不需要任何手动迁移。

### 4.2 金额精度方案
- 用户输入一律走 `parseYuanToCents()`：正则校验格式 → 按小数点拆开 → 整数运算合成分值。
- **刻意不使用** `parseFloat(x) * 100`，因为 `0.29 * 100 === 28.999999999999996`，会引入误差。
- 全程整型加减，只在渲染时 `(cents / 100).toFixed(2)`。

### 4.3 分摊余数规则
```js
base = Math.floor(totalCents / n);      // 每人基础份额
remainder = totalCents % n;             // 余数，最多 n-1 分
// 按参与人顺序，前 remainder 个人各多 1 分
```
例：100 分由 3 人均摊 → 34 / 33 / 33，合计 100，不会有 1 分钱「凭空消失」。

### 4.4 结算算法（贪心）
```
输入：净余额表
1. 拆成债权人数组（余额 > 0）和债务人数组（余额 = -余额）
2. 两个数组都按金额从大到小排序
3. 双指针：每次转账 amount = min(最大应收, 最大应付)
4. 转完必然有一方清零，指针后移，直到两数组走完
输出：转账列表（最多 n-1 笔）
```
- 复杂度 O(n log n)；n ≤ 4，结果必为最优（最少笔数）。
- 补充说明：在人数很多时，「最少转账笔数」本质上等价于**子集划分问题**，是 NP-hard 的，所以工程上采用贪心，在「用户可理解的规则」和「接近最优」之间取平衡。

### 4.5 XSS 防护
所有拼接进 `innerHTML` 的用户数据都经过 `esc()`：`& < > " '` 全部转义为 HTML 实体，恶意内容只会被当作文本显示。

### 4.6 代码结构（`index.html` 内 `<script>` 分区）
| 分区 | 内容 |
| --- | --- |
| 1. 常量与全局状态 | `DEFAULT_MEMBER_LIMIT` / `MIN_MEMBER_LIMIT` / `MAX_MEMBER_LIMIT`、`STORAGE_KEY`、`CATEGORIES`、内联 SVG 图标常量、`state.memberLimit` |
| 2. 通用工具函数 | `uid` / `fmt` / `todayStr` / `esc` / `parseYuanToCents` / `toast` |
| 3. 持久化与校验 | `save` / `load` / `normalizeData` / `exportJSON` / `importJSON` |
| 4. 核心计算 | `splitAmount` / `computeStats` / `computeTransfers` |
| 5. 渲染层 | `renderMembers` / `buildFormOptions` / `syncTagStates` / `renderStats` / `renderSettlement` / `renderExpenseList` / `refresh` |
| 6. 事件与初始化 | 表单提交、事件委托删成员/删支出、步进器「−/+」、付款人标签与原生 `select` 同步、导入导出、`init` |

关键逻辑均有中文注释，便于阅读与答辩讲解。

## 七、已知边界与后续可扩展方向

- **数据只在本机**：localStorage 不跨设备、不跨浏览器，且容量约 5MB（本项目数据量远达不到）。如需多人同步，需引入后端（REST/WebSocket）+ 数据库 + 乐观锁版本号。
- **结算笔数最少性**：n ≤ 4 时贪心即最优；人数扩大后可考虑「子集划分 + 剪枝」求精确最优。
- **可扩展**：多人非均摊（按比例/按份数）、消费限额提醒、月度报表图表、PWA 离线安装。

## 八、Android App（WebView 壳）

用**原生 Java + WebView** 把网页版打包成 Android App，网页业务逻辑零改动。

- **技术栈**：Java + AndroidX（appcompat/core），单 Activity + WebView，网页与资源打包进 `assets/` 离线加载。
- **离线可用**：`file:///android_asset/index.html`，无网络也能打开与记账。
- **移动端适配**（详见 [android/打包说明.md](file:///C:/Users/THUNDEROBOT/Documents/Trae-CN/default/android/打包说明.md)）：
  1. 软键盘：`adjustResize` + IME 高度回写 CSS 变量，只收窄 WebView 自身高度，由浏览器做最小幅度滚动，输入框不被遮挡、页面也不会被多滚一截；
  2. 安全区：Edge-to-Edge + `env(safe-area-inset-*)` 避让刘海与手势条；
  3. localStorage：`setDomStorageEnabled(true)` + `setDatabaseEnabled(true)`，数据落私有目录；
  4. 返回键：优先关弹层 → 再网页后退 → 最后退出；
  5. 导入导出：`onShowFileChooser` 走系统选择器；导出写入「下载」目录并唤起系统分享；
  6. 旋转：锁定竖屏 + `configChanges`，不重建 Activity；
  7. 防白屏：进度条 + 启动闪屏。
- **打包**：Android Studio 打开 `android/` → Run 运行；签名 APK 步骤见 `android/打包说明.md`。
- **现成 APK**：仓库根目录的 `宿舍账本-v1.1.apk` 为已构建产物（`gradlew assembleDebug`，v2 方案 debug 签名，versionCode 2），
  直接传到手机点击安装即可（需允许「未知来源应用」）；也可用 `adb install -r 宿舍账本-v1.1.apk` 安装。
- **桥接方式**：网页 `index.html` 尾部新增一段仅在 Android 环境生效的 `<script>`（普通浏览器自动空跑），
  只接管「导出落盘姿势 / 剪贴板 / 安全区传递 / 返回键弹层判断」，**不触碰任何业务函数与数据结构**。
